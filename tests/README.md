# Plugin tests

Each package owns `plugins/<id>/tests/` and its behavior index, `cases.json`. Use the package's `test` script for local checks. The repository root `pnpm test` runs Vitest package logic/UI state and Node package, repository and template tests once. It does not rebuild packages; run `pnpm build` first when changing distributed code. CI builds once before checking and testing. ChatUI build/check share vue-tsc's native incremental cache under its node_modules; the compiler still checks changed sources, dependencies and configuration.

- `logic/`: source algorithms, App scheduling and controlled frontend state.
- `contract/`: actual distributed SDK/package contracts, with privileged Host I/O substituted.
- `integration/`: real protocol SDK behavior against a controlled endpoint.
- Root `tests/repository/`: composition, signatures, immutable releases, localization and download behavior.
- Root `tests/templates/`: third-party template behavior.
- Root `tests/support/`: narrow shared fixtures; no second implementation of the Host.

Use `pnpm test:plugins`, `pnpm test:repository`, `pnpm test:tools`, `pnpm test:services` or `pnpm test:templates` for a selected layer. These are alternative selections; do not run all selections and the root suite in the same gate. `*.native.test.mjs` is the native runner suffix. Fixtures never enter automatic discovery.

`tests/cases/migration.json` records the old file hashes and new owners. Moving a test does not prove it passed. Full Agent interoperability and plugin business browser scenarios are owned here; nexus-terminal retains generic Host safety and lifecycle tests. Package-level tests use narrow controlled Host ports; the separate interoperability layer uses the real built Host and exact candidate archives. The interoperability layer currently discovers 54 testcases across Agent scheduling, tools, services and UI contracts. Browser coverage contains 70 scenarios under `tests/e2e/specs/<packageId>/`. Discovery counts describe scope, not a passing gate.

Retry and handshake policy tests use Node's native mock clock, preserving the actual threshold and call-count assertions. Real network, idle, backpressure and process-exit cases must retain their actual protocol conditions. No production timeout is shortened for test speed. Test reports and first failures belong to the invoking task's artifact directory; do not commit generated reports or packages.

The MCP service package owns the full tool/resource/prompt input-required map matrix, including all normalized state-only forms and malformed embedded request schemas. These execute the official protocol SDK directly. The Host keeps representative real governed transport and continuation round-trips; ordinary protocol input combinations do not create model Runs.

## Exact candidate Host interoperability

Build the plugin packages once with `pnpm build`, then run `pnpm prepare:interop <new-artifact-directory>` to sign a staging generation with a newly generated development key. This reuses the production package/release builders and never uses the official signing key.

Set `NEXUS_TEST_HOST_ROOT` to the built Host checkout/test artifact (with dependencies and its `tests/support/plugins/host-harness.mjs` API), `NEXUS_TEST_PLUGIN_SET` to the generated `staging-N` directory, and `NEXUS_TEST_ARTIFACT_DIR` to a fresh run directory. Execute `pnpm test:interop`. Missing artifacts fail immediately; no fallback to pinned releases and no silent skip. `pnpm test:browser` runs real plugin UI scenarios through the exact Host artifact's Playwright configuration and controlled fixtures; `pnpm check:browser` checks discovery and browser source types. `pnpm test:all` runs the ordinary suite, interoperability, browser checks and browsers. Build artifacts must be prepared beforehand. Validate pins a successful Host E2E source SHA and immutable application artifact. Its quality job builds and signs this plugin revision once, checks browser discovery/types, and runs source/package tests. Eight test shards restore the same compiled source and candidate archives, then use Node file-level and Playwright case-level native sharding for all 54 interoperability and 70 browser scenarios. Browser cases have independent Host/peer baselines; `fullyParallel` permits distributing cases across runners, while each runner keeps one worker to isolate its fixed ports. Each shard records the exact source/build/package combination and retains original failures. The development signing key is not distributed to shards; the runner image supplies protocol peers and cached dependencies, with an online install fallback when its dependency fingerprint differs. A missing new Host harness fails explicitly; initial cross-repository rollout needs a successful new Host gate before plugin Validate can complete.

The plugin tests consume the Host's test-artifact entry point instead of importing implementation modules. It uses the ordinary publisher trust, repository, package validation, installation, composition, grants and isolated execution paths. Archives are served byte-for-byte; the candidate App is never copied into a re-signed fixture. `combination.json` records both source fingerprints (including uncommitted changes), their complete file/hash manifests, Host compiled-output fingerprints, SDK/archive digests and exact package identities. Keep the file manifests with the aggregate hashes so a shard mismatch can be traced to its exact input; generated files are not silently excluded from this comparison. Each scenario keeps its database and setup/execute/drain timings; failures and cleanup errors remain failures. UI installation is covered here, while iframe rendering/approval interaction remains a browser responsibility.

Use a distinct artifact directory per run. The Host and candidate fingerprints in `combination.json` are part of the result; a previous Host PASS does not validate a new combination. `tests/e2e/fixtures/task-projects/` is the sole owner of real task projects. Browser helpers are imported from the Host test artifact's `e2e/support/agent-host/`, not copied into this repository. No Playwright-to-Node test wrappers remain.

Validate pins an immutable runner digest for all eight shards. Dispatch `dependency_cache=cold` disables the quality job's pnpm cache restore; `warm` uses the ordinary dependency cache. Both run every test against the same baked runner dependencies; this does not claim cold OS or image caches. Compare exact plugin/Host SHAs and runner digests before treating two runs as a cache experiment. GNU time metrics retain wall time, descendant CPU and the maximum individual process RSS, not aggregate concurrent RSS. Measurements never replace framework assertions or change failure status.

Browser fixtures declare the smallest real plugin composition needed by each scenario. ChatUI remains installed where rendering is asserted; protocol-only Host tests need no UI package. The initial composer submission and post-cancellation recovery stay in the real UI, while repeated App algorithm matrices may submit through the same real workspace API with independent operation IDs. A helper that already performs full navigation does not require an extra reload first. Full file bytes, GIF decoding, directory depth, grants, approvals, process cleanup and persistence assertions stay unchanged.
