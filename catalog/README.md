# Catalog

Catalog schema v2 aggregates independently released packages. It does not define a repository-wide package version or compatibility range. The publisher's exact signed manifest owns the package id/version, Host/backend/frontend SDK requirements and contribution kinds.

Build one package with `scripts/build-release.mjs`, retaining its original signed archive and `.release.json` descriptor. Aggregate explicitly selected descriptors with `scripts/build-catalog-release.mjs <catalog.json> <descriptor>...`. The aggregator verifies signature, every file hash, archive hash/size, manifest-derived compatibility and contribution kinds. It never rebuilds an unchanged package. An existing output with different bytes is rejected.

`official-publisher.json` contains the official public identity. A third-party package uses the same contract, verifier and signing pipeline with its own key. A key id or a label never grants execution permission or establishes official trust; the Host pins its trusted official identity independently. Catalog entries have no publisher-controlled compatibility verdict: the Host computes that result against its own version and SDK capabilities.

The `Aggregate catalog` workflow accepts new published descriptor URLs and optional `base_catalogs` URLs. It retains every base package version and original URL, downloads and verifies the corresponding original archives, then merges the new descriptors. Identical publisher/package/version/hash entries coalesce; a different hash for an existing identity fails. The `recommended_apps` input defaults to `["nexus.agent"]`. For each requested ID, aggregation requires an unambiguous publisher and checks its newest App manifest against the retained verified archives, selecting the highest version within each signed publisher/range whose Host range covers the requesting App. The selected execution reference must be self-provided backend code; its own UI is not inherited. Missing required dependencies prevent output. A custom partial directory may explicitly pass `[]`; it is not the default product recommendation. The local builder exposes the same check with `--require-app nexus.agent`; the downloader takes the App ID JSON array as its fourth argument. The workflow uploads only the new catalog into an existing draft release. Use a new catalog tag to retain the old catalog asset.

Package release/upload uses the separate `Release package` workflow. It checks existing repository releases for the same package/version before upload, refuses changed bytes across tags, and can fill missing assets after a verified partial upload. It never overwrites or deletes assets. Draft creation and publication are explicit operator actions. Templates are excluded from the product catalog; their execution references and local UI closure are checked as source consumers.
